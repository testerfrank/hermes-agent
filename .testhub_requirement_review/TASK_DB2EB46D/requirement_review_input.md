===== 注册登录需求.pdf =====

用户注册登录系统需求文档
1. 简介
1.1. 项目概述
本文档旨在定义[产品名称]平台的用户注册与登录功能的需求和规格。该功能是新用户进入
平台和老用户享受个性化服务的首要入口，其体验直接关系到用户的转化率和留存率。
1.2. 问题陈述
目前用户无法区分身份使用本平台。需要一个安全、便捷、灵活的账户体系，以便：
用户：可以拥有个人专属空间、保存数据、享受个性化服务。
业务：可以识别用户身份、进行用户分析、实现精准运营和营销。
1.3. 目标与范围
核心目标：
降低注册门槛：提供多种注册方式，提高用户转化率。
保障安全可靠：确保用户账户信息和隐私数据的安全。
简化登录流程：减少用户操作步骤，实现快速便捷登录。
为后续功能奠基：为用户画像、社交互动、付费订阅等高级功能提供基础账户体系。
范围：
本阶段需求涵盖：手机号注册/登录、邮箱注册/登录、第三方授权登录、忘记密码、登录状
态管理等功能。不包含：用户个人资料编辑、账户安全设置（如修改手机号、绑定微信等）、
用户注销流程，这些将列入后续版本规划。
3. 功能性需求
3.1. 注册功能
3.1.1. 手机号注册
FR1.1： 用户可选择“手机号注册”方式。
FR1.2： 用户需输入 11 位中国大陆手机号码，前端需进行格式校验。
FR1.3： 用户点击“获取验证码”后，系统应向该手机号发送一条 6 位数字的短信验证码。
FR1.4： 验证码有效期为 5 分钟，且同一手机号在 60 秒内只能获取一次。
FR1.5： 用户需输入正确的验证码以完成验证。
FR1.6： 用户需设置登录密码（需输入两次）。密码规则：至少 8 位，需包含字母和数字。
FR1.7： 用户阅读并勾选《用户协议》和《隐私政策》后方可注册。
FR1.8： 点击注册按钮后，系统需检查手机号是否已被注册。如已被注册，则提示“该手机号已存在，请直接登录或找回密码”。
FR1.9： 所有信息验证通过后，系统创建新账户，并自动登录跳转至首页或用户引导页。
3.1.2. 邮箱注册
FR2.1： 用户可选择“邮箱注册”方式。
FR2.2： 用户需输入邮箱地址，前端需进行格式校验。
FR2.3： 用户点击“获取验证码”后，系统应向该邮箱发送一封包含6位数字验证码的邮件。
FR2.4： 验证码有效期为 15 分钟。
FR2.5： 后续流程与手机号注册（FR1.5 - FR1.9）相同，校验邮箱是否已被注册。
3.1.3. 第三方账号授权登录（0Auth 2.0）
FR3.1： 用户可选择第三方授权登录（如：微信、苹果（i0S 端））。
FR3.2： 点击相应图标后，跳转至第三方授权页面。
FR3.3： 用户授权后，系统自动获取用户的唯一标识（0penID/UnionID），并检查是否已绑
定现有账户。
FR3.4： 如果是新用户，则要求其补充设置用户名（或使用第三方昵称）并完成注册。（注
意：为简化流程，可跳过设置密码环节，后续可在账户安全中设置）
FR3.5： 如果是老用户，则直接登录成功。
3.2. 登录功能
3.2.1. 账号密码登录
FR4.1： 用户可选择“账号密码登录”方式。
FR4.2： 用户可使用已注册的手机号/邮箱作为账号输入。
FR4.3： 用户输入登录密码。
FR4.4： 提供“记住密码”选项（默认不勾选），勾选后下次进入登录页自动填充账号和密码。
FR4.5： 点击登录后，系统验证账号和密码。失败时提示“账号或密码错误”。
3.2.2. 短信验证码登录
FR5.1： 用户可选择“短信验证码登录”方式。
FR5.2： 用户输入手机号并获取短信验证码（规则同 FR1.3-FR1.4）。
FR5.3： 输入正确验证码后，系统检查该手机号是否已注册。
已注册：直接登录。
未注册：自动为该手机号创建账户并登录（需弹窗告知用户并请求同意用户协议）。
3.3. 忘记密码
FR6.1： 在登录页提供“忘记密码”入口。
FR6.2： 用户需输入已注册的手机号/邮箱。
FR6.3： 通过短信或邮箱验证身份（发送验证码）。
FR6.4： 验证通过后，允许用户设置新密码（规则同注册）。
FR6.5： 密码修改成功后，提示用户并使用新密码重新登录。
3.4. 登录状态维护
FR7.1： 登录成功后，服务器应返回一个有效的 Token（如 JWT）。
FR7.2： 客户端（Web/App）应安全地存储该 Token（如 HTTPS-on1y Cookie 或 Secure
Storage）。
FR7.3： 后续所有 API 请求都应在 Header 中携带此 Token 进行身份验证。
FR7.4： Token 应设置有效期（如 7 天）。提供 Refresh Token 机制以在用户活跃时无感刷
新登录状态。
3.5. 退出登录
FR8.1： 在用户个人中心或设置页面提供“退出登录”按钮。
FR8.2： 点击后，清除客户端存储的 Token 及用户信息，并跳转至登录页或首页。
4. 非功能性需求
性能：
95%的注册/登录 API 请求响应时间应小于 500ms。
短信/邮件验证码应在 30 秒内送达。
安全性：
密码必须加盐哈希存储（如使用 bcrypt），严禁明文存储。
验证码需防爆破，连续输错 3 次验证码需要求重新获取。
接口需防重放攻击和脚本攻击。
使用 HTTPS 加密传输所有数据。
可用性：
系统整体可用性不低于 99.9%。
兼容性：
Web 端：支持 Chrome, Firefox, Safari, Edge 等主流浏览器最新两个版本。
Mobi1e 端：支持 i0S 和 Android 主流机型及系统版本。
5. 业务规则
BR1： 一个手机号/邮箱只能绑定一个主账户。
BR2： 一个第三方账号（如微信）在同一环境下只能绑定一个主账户。
BR3： 用户通过第三方授权登录后，可引导其绑定手机号或邮箱，以备第三方登录失效时
使用。
