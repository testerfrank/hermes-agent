## 二、活动订单退款逻辑变更（优化项2）
### 2.1 状态与按钮显示规则
| 奖励类型 | 订单状态条件 | 取消报名按钮 | 申请退款按钮 | 逻辑说明 |
| ：--- | ：--- | ：--- | ：--- | ：--- |
| **发盲盒** | 有任意盲盒已开启 | 不展示 | 展示（订单完成后） | 订单状态变为“已完成” |
| **发盲盒** | 盲盒已拆且券未使用 | 不展示 | 展示 | 可申请退款，退款后回收券 |
| **发盲盒** | 盲盒已拆且券已核销 | 不展示 | 不展示 | 点击退款提示：“活动奖励已使用，无法申请退款” |
| **发优惠券** | 有任意券已核销 | 不展示 | 不展示 | 订单状态变为“已完成” |
| **发优惠券** | 所有券均未使用 | 展示 | - | 取消报名即退款并回收券 |
### 2.2 用户端操作链路
1. **报名发优惠券**：
- 券未使用：可取消报名 -> 回收券并退款。
- 券已使用：不可取消报名，不可申请退款。
2. **报名发盲盒**：
- 盲盒未拆：可取消报名 -> 回收盲盒并退款 -> 可重新报名。
- 盲盒已拆：不可取消报名，可申请退款 -> 退款后不可再报名，回收开出的券。
- 盲盒已拆且券已用：不可取消报名，不可申请退款。

## 三、活动黑名单功能（优化项3）
### 3.1 后台管理需求
| 功能点 | 详细需求 |
| ：--- | ：--- |
| **黑名单入口** | 在“新建/编辑活动”页面增加“设置黑名单”入口（非必填）。 |
| **数据管理** | 1. 通过上传Exce1/CSV文件（仅含用户手机号列）导入。<br>2. **每次导入为全量替换**，即新列表完全覆盖旧列表。<br>3. 支持按手机号精确搜索已导入的黑名单数据。 |
| **界面展示** | 1. 弹窗列表展示当前活动的所有黑名单手机号。<br>2. 清晰提示导入为覆盖操作。 |
### 3.2 客户端拦截需求
- **校验时机**：用户点击“立即报名”时。
- **拦截规则**：校验当前登录用户手机号是否在活动黑名单中。
- **提示信息**：若在黑名单中，则提示：“抱歉，工作人员暂不可报名”。

## 四、报名发放优惠券功能（优化项4）
### 4.1 后台活动配置需求
| 配置项 | 详细需求 |
| ：--- | ：--- |
| **奖励类型** | “报名后发放奖励”选项增加“优惠券”（与“盲盒”为**单选**）。 |
| **关联盲盒** | 1. 选择“盲盒”时显示。<br>2. 仅能关联**一个**已有的盲盒活动。<br>3. 需设置“盲盒发放数量”（正整数，≤10）。 |
| **关联优惠券** | 1. 选择“优惠券”时显示。<br>2. 可关联多个不同的优惠券模板，**最多10个**，超限提示。<br>3. 需为每个模板设置“发放数量”（正整数，≤10）。 |
### 4.2 客户端展示需求
- 用户报名后，根据发放的奖励类型（优惠券或盲盒）展示对应的结果弹窗。
- 弹窗跳转逻辑遵循第一部分（优化项1）中定义的规则。

## 五、 DMS门店数据查看（优化项5）
### 5.1 DMS模块新增
- 在DMS系统中新增 **“销售活动数据查询”** 菜单模块。
### 5.2 数据查询逻辑
- **数据源**：仅展示运营平台创建且已通过“下发门店”开关下发到该门店的活动数据。
- **匹配规则**：数据与门店的匹配依据为用户报名时填写的 **“到访门店”**。若该字段为空，则DMS无法看到该条数据。
### 5.3 数据列表字段
| 字段名 | 说明 |
| ：--- | ：--- |
| 用户手机号 | 报名用户的手机号 |
| 报名奖励类型 | 盲盒 / 优惠券 |
| 盲盒编码 | 奖励为盲盒时显示 |
| 优惠券编码 | 奖励为优惠券时显示；或盲盒开出的优惠券编码 |
| 盲盒状态 | 奖励为盲盒时显示（如未开启、已开启） |
| 奖品/优惠券名称 | 盲盒开出的奖项名，或直接发放的优惠券名称 |
| 优惠券状态 | 优惠券的当前状态（如未核销、已核销） |
| 操作 | 若优惠券状态为“未核销”，则显示“核销优惠券”按钮，门店可操作核销 |
### 5.4 总部视角扩展
- 总部或大区视角查看时，需在以上数据基础上增加：**门店编码、门店名称、所属大区、所属小区**。
