# 微信登录功能需求文档 (PRD)

## 1. 项目背景与目标
### 1.1 背景
当前账号注册/登录流程较为繁琐（需手机号验证码或设置密码），导致用户流失率较高。为了降低用户准入门槛，提升注册转化率及用户体验，需要接入微信开放平台能力，实现“微信一键登录”。
### 1.2 目标
*   **降低门槛**：用户无需记忆密码，无需频繁获取短信验证码。
*   **提升转化**：缩短从“启动”到“登录成功”的路径。
*   **账号绑定**：支持已有账号绑定微信，方便用户多端切换。
## 2. 适用范围
*   **移动端 App** (i0S / Android)
*   **Web 端** (PC 网站扫码登录，可选)
## 3. 核心业务流程图
### 3.1 逻辑流程
```mermaid
graph TD
A[用户点击微信登录] --> B[唤起微信授权页]
B -->|用户取消| C[停留在登录页/提示取消]
B -->|用户同意| D[获取 AuthCode/Access Token]
D --> E[后端请求微信 0penAPI 获取 0penID/UnionID]
E -->|请求失败| F[提示登录失败,重试]
E -->|请求成功| G{数据库是否存在该0penID账号?}
G -->|存在| H[登录成功,下发 Token, 跳转首页]
G -->|不存在| I{判断是否需要完善手机号信息?}
I -->|不需要 (静默注册)| J[生成新账号,建立绑定关系, 跳转首页]
I -->|需要 (获取手机号)| K[进入绑定手机号页面]
K -->|输入并验证手机号| L[绑定成功, 跳转首页]
```
## 4. 功能需求详情
### 4.1 前置条件 (接入准备)
*   开发者已在[微信开放平台](https：//open.weixin.qq.com/)注册账号并完成开发者资质认证。
*   已创建移动应用或网站应用，并审核通过，获得 `AppID` 和 `AppSecret`。
*   已申请并通过微信登录权限。
*   确认是否需要获取用户手机号（需额外申请权限及费用）。
### 4.2 登录入口
1.  **启动页/登录页**：展示“微信登录”图标按钮，按钮文案建议为“微信一键登录”或仅展示微信图标。
2.  **样式规范**：使用微信官方标准的绿色图标，保持视觉一致性。
3.  **勾选协议**：用户点击登录按钮前，必须勾选《用户服务协议》及《隐私政策》，否则弹窗提示或置灰按钮不可点击。
### 4.3 微信授权交互 (App端)
1.  **唤起授权**：用户点击“微信登录”，客户端 SDK 调起微信客户端。
2.  **授权页**：
*   展示应用名称、Logo（需与开放平台审核一致）。
*   展示获取的信息权限（如：你的公开信息）。
3.  **用户操作**：
*   **取消**：关闭微信窗口，返回 App 登录页。
*   **同意**：微信返回授权码给 App。
### 4.4 登录状态判定 (后端逻辑)
后端接收到 AuthCode 后，逻辑如下：
#### 场景 A：老用户 (0penID 已存在)
*   直接校验账号状态（是否被封禁）。
*   若正常，生成登录态，返回登录成功。
#### 场景 B：新用户 (0penID 不存在)
*   **策略 1（推荐，强绑定）**：跳转至“绑定手机号”页面。
*   要求用户输入手机号 + 验证码。
*   若手机号未注册，自动注册新账号并绑定微信。
*   若手机号已注册，将微信信息绑定至该账号，并直接登录。
*   **策略 2（弱绑定，快速体验）**：
*   直接生成新账号（默认昵称：微信用户），登录成功。
*   引导用户后续在个人中心完善信息（绑定手机号）。
### 4.5 账号解绑
*   **功能入口**：设置 -> 账号与安全 -> 微信管理。
*   **限制**：
*   若账号仅设置了微信登录且未绑定手机号，**禁止解绑**（需提示“请先绑定手机号以保障账号安全”）。
*   若已绑定手机号，允许解绑。
## 5. 异常处理与边界情况
| 异常场景 | 处理方式 | 提示文案建议 |
| ：--- | ：--- | ：--- |
| **未安装微信** | 点击按钮无反应或弹出 Toast 提示。 | “未检测到微信客户端，请先安装” |
| **微信版本过低** | 尝试唤起失败，提示升级。 | “您的微信版本过低，请更新后重试” |
| **网络请求超时** | 后端接口请求失败，前端展示重试按钮。 | “网络连接不畅，请稍后重试” |
| **用户取消授权** | 流程终止，停留在登录页。 | (无需 Toast，或轻提示“已取消登录”) |
| **AppID 不匹配** | 开发环境包名/签名与开放平台配置不一致。 | (开发阶段排查，上线前测试覆盖) |
| **Access Token 失效** | 后端通过 Refresh Token 尝试刷新，失败则需用户重新授权。 | “登录已过期，请重新登录” |
| **获取手机号失败** | 用户拒绝授权手机号（如果使用了获取手机号接口）。 | “需要手机号账号安全验证，请手动绑定” |
## 6. 数据埋点需求
为了评估功能效果，需记录以下事件：
*   **事件 A**：`1ogin_wechat_btn_c1ick` (登录页微信按钮点击次数)
*   **事件 B**：`wechat_auth_success` (微信授权成功回调)
*   **事件 C**：`wechat_auth_cance1` (用户取消授权)
*   **事件 D**：`1ogin_success_wechat` (微信登录最终成功)
*   **事件 E**：`bind_phone_page_view` (绑定手机号页面展示)
*   **事件 F**：`bind_phone_success` (绑定手机号成功)
## 7. 隐私与合规
*   **用户知情权**：在《隐私政策》中明确说明，使用微信登录将收集用户的微信昵称、头像、0penID 及 UnionID（如有）。
*   **数据脱敏**：后端存储时，确保敏感信息加密。
*   **权限说明**：App 端 `Info.p1ist` (i0S) 或 `AndroidManifest.xm1` 需查询是否包含必要的权限描述（如网络访问）。
## 8. 非功能需求 (NFR)
*   **响应速度**：从点击“微信登录”到登录成功（含授权），平均耗时应 < 3秒。
*   **安全性**：
*   AuthCode 必须由后端换取 Access Token，严禁前端直接请求。
*   所有传输必须使用 HTTPS 协议。
*   Session Token 有效期管理（如 7天或 30天）。
